# 绿联 NAS 配置教程

本文以绿联 NAS 的 UGOS/UGOS Pro 系统为例，整理从首次开机到日常使用的基础配置流程。不同型号和系统版本的菜单名称可能略有差异，但配置思路基本一致：先保证存储可靠，再配置账号权限，最后开放共享、备份和远程访问。

## 1. 配置前准备

建议先准备好以下内容：

- NAS 主机、硬盘、网线和稳定电源。
- 一台连接同一局域网的电脑或手机。
- 路由器管理权限，方便查看 NAS IP、设置 DHCP 静态租约和端口转发。
- 绿联云 App 或浏览器管理入口。
- 需要迁移的数据清单，先区分照片、文档、影视、容器数据和备份数据。

硬盘安装前建议确认容量、健康状态和用途。如果使用多块硬盘，尽量选择容量、转速和健康状态接近的硬盘，避免阵列性能和可用容量被较弱的硬盘拖累。

## 2. 首次开机与初始化

1. 将硬盘装入 NAS 硬盘位。
2. 使用网线连接 NAS 和路由器或交换机。
3. 接通电源并开机，等待指示灯稳定。
4. 在手机 App 或浏览器中搜索设备。
5. 按提示设置管理员账号、登录密码、设备名称和时区。

管理员账号不要使用过于简单的名称和密码。建议开启二次验证，并单独创建日常使用账号，管理员账号只用于系统配置和维护。

## 3. 固定局域网 IP

NAS 作为长期运行的存储服务，建议固定局域网 IP，避免重启后地址变化导致 SMB、WebDAV、Docker 服务或媒体库失效。

推荐做法是在路由器中设置 DHCP 静态租约：

1. 登录路由器后台。
2. 找到已连接设备列表。
3. 记录 NAS 的 MAC 地址。
4. 为 NAS 绑定固定 IP，例如 `192.168.1.10`。
5. 重启 NAS 或重新获取网络地址。

如果在 NAS 系统内手动设置静态 IP，需要同时填写网关、DNS 和子网掩码。家庭网络中常见配置如下：

```text
IP 地址：192.168.1.10
子网掩码：255.255.255.0
网关：192.168.1.1
DNS：192.168.1.1 或 223.5.5.5
```

## 4. 创建存储池和存储空间

进入存储管理页面后，先创建存储池，再创建存储空间。常见方案如下：

- 单盘 Basic：容量利用率最高，但硬盘损坏后数据不可恢复。
- RAID 1：两块硬盘互为镜像，牺牲一半容量换取单盘故障保护。
- RAID 5：至少三块硬盘，兼顾容量和冗余，允许一块硬盘损坏。
- RAID 6：至少四块硬盘，允许两块硬盘损坏，更适合大容量硬盘。

家用两盘位 NAS 通常优先选择 RAID 1。四盘位以上如果需要兼顾容量和安全，可以考虑 RAID 5 或 RAID 6。RAID 不是备份，它只能降低硬盘故障导致的停机风险，不能防止误删、勒索软件、系统故障或整机损坏。

创建完成后，建议开启以下功能：

- S.M.A.R.T. 健康检测。
- 磁盘坏道或快速检测计划。
- 存储池异常通知。
- 回收站或快照功能，如果当前系统支持。

## 5. 创建共享文件夹

共享文件夹建议按用途拆分，不要把所有数据都堆在一个目录中。可以参考以下结构：

```text
Photos      照片和视频
Documents   文档资料
Media       影视和音乐
Backup      电脑和手机备份
Docker      容器配置和持久化数据
Public      临时共享文件
```

创建共享文件夹时需要注意权限：

- 私人数据只授权给对应用户。
- 家庭共享目录可以授权给家庭成员组。
- `Public` 目录只用于临时交换文件，不建议长期保存重要数据。
- Docker 数据目录不要随意开放写权限。

如果系统支持共享文件夹回收站，建议对常用目录开启。这样误删文件时可以先从回收站恢复。

## 6. 配置用户和权限

建议至少创建三类账号：

- 管理员账号：只用于系统维护。
- 日常账号：用于电脑、手机、平板访问文件。
- 服务账号：用于 Docker、备份任务或媒体服务。

权限配置原则是最小权限：

- 只给用户访问自己需要的共享文件夹。
- 能只读就不要给读写。
- 不要多人共用管理员账号。
- 对外共享链接设置有效期和访问密码。

如果多人使用 NAS，可以创建用户组，例如 `family`、`media`、`backup`，再给用户组授权。这样后续新增用户时，只需要把用户加入对应组即可。

## 7. 开启 SMB 文件共享

Windows 和 macOS 局域网访问文件时，SMB 是最常用的协议。

在 NAS 中开启 SMB 服务后，可以在 Windows 文件资源管理器地址栏输入：

```text
\\192.168.1.10
```

也可以映射网络驱动器：

1. 打开“此电脑”。
2. 选择“映射网络驱动器”。
3. 输入共享路径，例如 `\\192.168.1.10\Documents`。
4. 勾选“登录时重新连接”。
5. 输入 NAS 用户名和密码。

macOS 可以在 Finder 中选择“前往”中的“连接服务器”，输入：

```text
smb://192.168.1.10
```

SMB 建议只在局域网内使用，不建议直接暴露到公网。

## 8. 手机照片自动备份

绿联 NAS 的常见使用场景是手机照片自动备份。配置步骤一般如下：

1. 在手机安装绿联云 App。
2. 登录自己的 NAS 账号。
3. 打开照片备份功能。
4. 选择备份目录，例如 `Photos/手机型号`。
5. 设置是否仅在 Wi-Fi 下备份。
6. 保持 App 必要的后台运行权限。

首次备份照片数量较多时，建议让手机连接电源并保持 Wi-Fi 稳定。备份完成后，可以抽查 NAS 目录中的照片数量和时间范围，确认没有遗漏。

## 9. 配置 Docker

如果设备支持 Docker，可以用它运行常见服务，例如 Jellyfin、qBittorrent、Alist、Home Assistant、Gitea 等。

Docker 使用前建议先规划目录：

```text
Docker/
  jellyfin/
    config/
    cache/
  qbittorrent/
    config/
  downloads/
```

运行容器时重点关注三类映射：

- 端口映射：决定从浏览器访问哪个端口。
- 目录映射：决定配置和数据保存在哪里。
- 权限设置：决定容器能访问哪些文件夹。

以 Jellyfin 为例，常见目录规划如下：

```text
/config  -> /Docker/jellyfin/config
/cache   -> /Docker/jellyfin/cache
/media   -> /Media
```

容器配置和媒体文件要分开保存。升级或重建容器时，只要持久化目录不变，配置和媒体库就可以继续使用。

## 10. 远程访问方案

远程访问有多种方式，安全性和复杂度不同：

- 官方远程访问：配置简单，适合普通文件管理。
- VPN：安全性较高，适合长期远程管理。
- DDNS 加端口转发：灵活，但需要谨慎配置安全策略。
- 反向代理：适合多个 Web 服务统一通过域名访问。

不建议直接把 NAS 管理后台、SMB、SSH 暴露到公网。如果必须开放公网访问，建议做到：

- 使用强密码和二次验证。
- 只开放必要端口。
- 后台管理端口不要使用默认端口。
- 启用 HTTPS。
- 定期查看登录日志。
- 对重要目录保留离线备份。

如果路由器支持 WireGuard、OpenVPN 或 Tailscale，优先使用 VPN 访问家庭内网。这样外出时可以像在家里一样访问 `192.168.1.10`，同时减少公网暴露面。

## 11. 备份策略

NAS 本身不是终点备份。更稳妥的策略是 3-2-1：

- 至少保留 3 份数据。
- 使用 2 种不同介质。
- 至少 1 份放在异地或离线位置。

家庭场景可以这样设计：

- 手机照片自动备份到 NAS。
- 电脑重要目录定时备份到 NAS。
- NAS 重要目录定期同步到移动硬盘。
- 特别重要的文档再同步到云盘或异地设备。

移动硬盘备份完成后建议断开连接，避免 NAS 被误操作或恶意软件影响时，备份盘也被一起破坏。

## 12. 系统维护

日常维护建议按月检查：

- 系统更新和应用更新。
- 硬盘 S.M.A.R.T. 状态。
- 存储池容量和健康状态。
- 备份任务是否成功。
- 异常登录和系统日志。
- Docker 容器是否占用过多 CPU、内存或空间。

存储空间建议保留至少 10% 到 20% 的余量。长期接近满盘会影响性能，也会增加服务异常的概率。

## 13. 常见问题

### 13.1 电脑找不到 NAS

先确认电脑和 NAS 是否在同一局域网。可以在电脑上执行：

```bash
ping 192.168.1.10
```

如果 ping 不通，检查网线、路由器设备列表、NAS IP 和防火墙。如果 ping 通但 SMB 无法访问，检查 SMB 服务是否开启、账号权限是否正确。

### 13.2 SMB 访问提示没有权限

常见原因是 Windows 缓存了旧账号。可以在 Windows 凭据管理器中删除对应 NAS 地址的旧凭据，然后重新连接并输入正确账号。

也可以执行：

```cmd
net use
net use \\192.168.1.10 /delete
```

再重新访问共享路径。

### 13.3 Docker 容器重启后数据丢失

通常是没有正确配置目录映射。容器内部目录如果没有映射到 NAS 的共享文件夹或持久化路径，删除容器后数据也会消失。

修复思路：

1. 停止容器。
2. 确认应用的数据目录。
3. 把数据目录映射到 `Docker/应用名` 下。
4. 重新创建容器。

### 13.4 硬盘出现异常怎么办

不要反复重启或强行重建阵列。先查看存储池状态和硬盘 S.M.A.R.T. 信息。如果已经有重要数据风险，优先备份仍可读取的数据，再更换硬盘或执行修复。

如果使用 RAID 1、RAID 5 或 RAID 6，更换故障硬盘后通常需要等待阵列重建。重建期间不要断电，也不要进行大量读写操作。

## 14. 推荐初始化清单

首次配置完成后，可以按下面清单复查：

- 固定 NAS 局域网 IP。
- 创建管理员账号和日常账号。
- 开启二次验证。
- 创建存储池和共享文件夹。
- 配置 SMB 局域网访问。
- 配置手机照片备份。
- 为重要目录开启回收站或快照。
- 配置至少一份外部备份。
- 检查系统通知和硬盘健康检测。
- 确认远程访问没有暴露高风险服务。

完成以上配置后，绿联 NAS 就可以作为家庭文件中心、照片备份中心、媒体库和轻量服务器使用。后续再根据实际需求逐步增加 Docker 应用、异地备份和自动化任务，会比一次性堆满功能更稳定。
